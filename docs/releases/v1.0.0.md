## Warehouse and Dispatch issue

The reported Warehouse-to-Dispatch case remains open. The UF-06 and UF-07
execution guide identifies missing visible lots and an unidentified picking
preparation. Those prerequisites must be established in the authorized runtime
context before the complete workflow can be verified.

The current Mobile client lists picking work from `/api/v1/fulfillments` and
Dispatch readiness from `/api/v1/dispatch-readiness`. Those projections
require a current Fulfillment backed by a Physical Allocation and the
applicable active Warehouse grants. The API also has a legacy inventory
reservation flow exposed through different projections; the Mobile client
does not read that legacy list. The two lifecycles are not interchangeable.
Warehouse/Dispatch fixture tests exercise explicit grants and prepared
fulfillment state, but do not prove the missing runtime case or Render data.

Closing this issue requires the exact Tenant/Workspace and authorized account,
Warehouse grants, reservation/order identifier and create path, the destination
screen, and the observed API response. Valid stock/lots, confirmed order
backing, and a prepared Fulfillment/Physical Allocation may be required by the
chosen lifecycle. No authorization or business semantics were changed in this
candidate.

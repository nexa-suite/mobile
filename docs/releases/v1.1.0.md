## Scope

Client code follows the eleven canonical context roots and explicit domain,
application, infrastructure and presentation layers. Runtime modules exist
only where code exists; Payments, Notifications and Business Traceability
remain documented context roots without fabricated capabilities. Technical
foundations and the app composition root remain separate from the contexts.

Field ordering follows the accepted Direct Order scope in
[Blueprint decision PR 33](https://github.com/nexa-suite/blueprint/pull/33).
The client validates confirmed and pending-prepaid creation receipts, preserves
frozen request bodies and explicit same-key retries, and retains legacy
Purchase Request intents without replaying them as Direct Orders.

Inventory and Fulfillment exchange narrow public read contracts. Context-owned
metadata stays behind infrastructure adapters. Protected document presentation
uses an application rendering port implemented with Android PDF APIs; pixels
are bounded and parser inputs use transient private files.

The API retains authority for authentication, scope, pricing, commercial
commitments, stock, credit, payment, fulfillment and delivery. Buyer Mobile
remains a separate TARGET. The [Sprint mapping](../sprint-1-2-implementation-traceability.md)
records all 36 original Mobile PBIs and their evidence limits.
